# Demo Q&A — Aazhiyam-AI

## 1. What does your project do?
Aazhiyam-AI is an offline-first, browser-based platform that helps reduce ship noise pollution in sensitive ocean zones. It classifies hydrophone (underwater) audio to detect vessel noise, visualizes ship movement on a 3D digital twin of the ocean zone, and uses an AI copilot to recommend "quiet path" adjustments — like speed or route changes — to minimize acoustic impact on marine life.

## 2. What problem does it solve?
Ship noise disrupts communication, navigation, and feeding behavior in marine species like dolphins, dugongs, and turtles — especially in protected or ecologically sensitive zones. Aazhiyam-AI gives maritime operators a practical, data-driven way to reduce that impact without needing constant internet connectivity, making it usable even in remote coastal areas.

## 3. What's the offline vs online scope?
- **Offline**: Audio classification (TensorFlow.js) and the 3D digital twin (Three.js) run entirely in-browser, no internet needed.
- **Online (with fallback)**: The Gemini-powered copilot needs internet for live AI responses. If unavailable, the system automatically falls back to pre-built, scenario-specific recommendations — so the demo and real-world use never break due to connectivity issues.

## 4. What's the tech stack?
- **Frontend**: HTML/CSS/JS, Three.js (3D digital twin), TensorFlow.js (audio classification)
- **Backend**: Python (Flask), Flask-CORS, python-dotenv
- **AI**: Google Gemini API (gemini-3.6-flash) with a hardcoded fallback response system
- **Data**: Scenario-based JSON files (zone, noise level, species, vessel data)

## 5. How does the Gemini fallback system work?
Every copilot request first tries calling the Gemini API. If it succeeds, the response is marked `"responseSource": "gemini"`. If Gemini fails (auth issue, rate limit, or no internet), the system automatically returns a pre-written, scenario-accurate response and marks it `"responseSource": "fallback"` — so the user always gets a relevant answer, and the demo never crashes on stage.

## 6. What's the demo flow?
1. Show hydrophone audio being classified in real time (browser-based, offline)
2. Show the 3D digital twin visualizing vessel positions and noise zones
3. Ask the AI copilot a question about reducing noise in a selected zone
4. Show the generated compliance report with recommendations, zone data, and affected species

## 7. What challenges did you face?
- Gemini API key generated by our college/Workspace Google account was an unsupported OAuth-style token (`AQ.Ab8...`) instead of a standard API key (`AIzaSy...`), causing intermittent 401 errors. We handled this by building a robust fallback system so the app degrades gracefully instead of failing.
- Debugged and resolved several GitHub setup issues (nested folders, accidental secret exposure in commit history).
- Fixed empty scenario data files and a request-key mismatch bug that caused all scenarios to incorrectly return Scenario A's data.
